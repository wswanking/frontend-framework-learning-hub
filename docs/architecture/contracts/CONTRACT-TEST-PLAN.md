# IOT-DOMAIN-001：契约测试计划

## 目标

证明领域契约独立于框架、结果可复现、权限不泄露、异常可处理，并为三个框架提供同一组验收基准。

## 最小测试矩阵

| 类别 | 必测案例 |
| --- | --- |
| 确定性 | 相同 seed/query 得到相同数据、排序与事件顺序；不同 seed 仅改变演示数据。 |
| 租户隔离 | 切换 tenant 后无前租户资源；跨租户 ID 返回 FORBIDDEN。 |
| 权限 | viewer 无写权限；operator 可控制设备但不能编辑产品；tenantAdmin 可管理本租户。 |
| 查询 | 分页边界、排序、空结果、时间范围、筛选组合。 |
| 领域规则 | DP 转换、产品标识唯一、设备离线控制、OTA 阈值暂停与回滚历史。 |
| 异常 | slow、partialFailure、forbidden、offline 和超时均具有规范错误语义。 |
| 事件 | 订阅追加、取消订阅、OTA/遥测事件顺序和重复防护。 |

## 通过标准

- 所有 service 的正常、空、无权限和失败场景均有测试。
- 契约测试不依赖 React、Vue、Angular 或 DOM。
- 三个应用在引入契约后只能做 UI 适配，不得改写业务结果。

## 审核检查

## 2026-09-20 跨端 DTO 比对增量

三端各自的 `src/contract-parity.spec.ts` 在 Node 环境调用本端 Dashboard、地理、产品、设备、规则、固件、OTA、租户服务，导出固定 seed、租户和 UTC 时间窗下的实际 DTO 与错误对象。仓库外层 `node tools/diagnose-all.mjs parity` 只调度本端测试并逐字段比较输出，不提供共享运行时实现；`diagnose` 和 `verify` 也包含该门禁。

当前覆盖 Dashboard 的 7 个场景、地理的 8 个场景，以及产品、设备、规则、固件、OTA、租户各自的列表、筛选列表、详情、跨租户拒绝、离线共 30 个场景。另用每次新建的内存 Storage 核对产品与设备的 11 个状态操作结果，以及规则创建/启用/事件执行与日志、固件创建/验证/发布/归档、租户创建与成员变更、OTA 预览/创建/启动/暂停/恢复/取消等 28 个结果。OTA 升级完成、创建反向任务、回滚完成、设备历史及重建服务后读取占 10 个结果；失败暂停、重试、完成、历史与重载占 8 个结果，合计 102 个。OTA 只读详情用不存在的任务核对 NOT_FOUND；其他五个详情核对真实种子实体。仍需覆盖更完整的命令失败分支、其他事件历史及权限角色矩阵，不能替代本计划的完整矩阵或 REVIEW-003。
