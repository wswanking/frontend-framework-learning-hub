# ADR-001：采用文档先行的 AI 驱动开发循环

## 状态

已接受，2026-08-23。

## 背景

仓库需要长期、多轮、跨三个框架协作。只有代码树不足以向后续 AI 提供产品边界、当前阶段和未完成项，容易造成重复脚手架、三端业务漂移和模板残留。

## 决策

以 `docs/` 作为事实与决策中心，以 `AGENTS.md` 作为每次会话入口。实现任务按“阅读上下文、映射需求、更新计划、最小实现、验证、回写”的循环进行。

## 后果

新功能需具备需求编号和验收方式，初期文档成本略有增加；后续会话可从[工程上下文](../../CONTEXT.md)恢复上下文；三端实施可追踪到同一业务契约。
