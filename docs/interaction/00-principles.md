# 交互原则与通用状态

## 设计目标

- 让操作者优先理解设备和业务状态，再进行操作。
- 让每个不可逆或高影响操作在执行前看见影响范围。
- 让三框架保持相同的信息架构、字段语义和状态反馈，但允许控件实现不同。

## 全局框架

左侧主导航、顶部上下文栏、内容区和可选详情抽屉。顶部固定展示当前租户、时间范围（如适用）、主题、通知和当前 Mock 身份。上下文变更后，页面应清晰提示正在刷新或已更新。

## 通用状态

| 状态 | 界面行为 | 用户动作 |
| --- | --- | --- |
| 初始加载 | 骨架或局部加载占位，不遮挡已完成区域 | 可取消长请求或返回 |
| 空数据 | 说明原因、给出创建/清除筛选入口 | 创建、重置、返回 |
| 局部失败 | 保留成功区域，在失败卡片显示重试 | 重试、查看详情 |
| 无权限 | 解释没有何种权限，不泄露受限数据 | 返回或联系管理员 |
| 未保存 | 页签/标题显示未保存标记 | 保存、放弃、继续编辑 |
| 高风险操作 | 二次确认中展示对象数量、影响和后果 | 确认或取消 |

## 反馈与可访问性

- 成功、警告、错误同时使用图标、文本和颜色；通知可被读屏读取。
- 弹窗打开时焦点进入弹窗，关闭后回到触发控件；Escape 可取消非破坏性弹窗。
- 键盘 Tab 顺序与视觉顺序一致；图表提供数据摘要/表格替代入口。
- 表单字段的错误显示在字段附近，并在提交后聚焦第一个错误。

## 主题与响应式

支持亮色、暗色和跟随系统，存储在本地。桌面采用多列；平板折叠侧栏；手机将筛选、地图详情和表格操作收纳为抽屉或底部面板，核心数据不依赖悬浮操作。
