# 回滚 Runbook

## 准入

- 仅回滚到发布记录中 `previousVerifiedVersion` 指向的上一已验证版本。
- production 回滚由发布负责人决定；AI 只能准备步骤和记录结果。
- 保存当前故障版本、环境、时间、影响、负责人和触发 Issue。

## 步骤

1. 冻结新的 production 发布，记录当前部署版本和故障现象。
2. 在托管平台重新部署上一已验证版本，禁止从未验证工作区临时重建。
3. 验证入口可访问、四个构建产物可加载、固定 seed 数据一致、关键 Dashboard/设备/OTA 路径可读。
4. 执行全量自动化检查，并记录命令、时间和结果。
5. 更新回滚记录中的原因、影响、执行人、完成时间和复验结论。
6. 为根因创建或关联 Issue；在修复重新验收前保持故障版本不可发布。

## 回滚后最低复验

- 根门户与 React、Vue、Angular 均能加载。
- `npm test` 与 `npm run lint` 通过。
- 租户隔离、规则禁用、固件校验和 OTA 阈值保护仍生效。
- 发布负责人记录“恢复成功”或“仍异常”，不得省略结论。
