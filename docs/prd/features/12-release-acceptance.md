# PRD：发布、回滚与验收

| 项目 | 内容 |
| --- | --- |
| 需求编号 | IOT-RELEASE-001 |
| 优先级 | P1 |
| 状态 | 需求保留，待重新实现与验收（2026-09-16） |
| 验收门禁 | 用户授权的自动化发布门禁 |

## 目标与边界

定义前端项目从本地验证到预览、正式发布和回滚的可审计流程。当前不绑定具体云厂商或发布平台，但所有发布证据必须归档在仓库。

## 环境与交互

| 环境 | 用途 | 数据/权限 | 准入 |
| --- | --- | --- | --- |
| local | 开发和快速验证 | 本地 Mock、开发者 | 静态检查和目标测试 |
| preview | 产品/测试评审 | 固定 seed Mock、受控链接 | 构建通过、变更记录、测试证据 |
| production | 正式演示/交付 | 已批准版本、只读演示数据 | 全部门禁通过、发布负责人批准 |

发布记录必须包含版本、提交/变更、需求/任务/Issue、环境、测试结果、已知风险、负责人、回滚步骤和验收链接。

## 业务规则

- production 发布前：构建与测试通过；高严重度 Issue 已关闭或被正式豁免；所有阻塞审核已有结论；回滚版本可用。
- 任何部署失败、性能/功能异常或验收拒绝都创建 Issue 和变更记录。
- 回滚只允许回到上一已验证版本；回滚后必须补充原因、影响和复验结论。

## 验收条件

- Given 预览发布，When 生成发布记录，Then 可追溯到需求、任务、测试和审核材料。
- Given 缺少回滚步骤或审核结论，When 尝试标记正式发布，Then 发布清单判定不准入。
- Given 发布后发现阻塞问题，When 回滚，Then 记录版本、原因、时间、负责人和回滚后的验证结果。

## 本轮验收方式

用户已明确授权“无需审核，满足验收标准就行”。正式发布须通过全仓构建、测试、静态检查、零未处理高严重度 Issue、上一已验证版本与完整回滚步骤检查；结果写入验收记录。
