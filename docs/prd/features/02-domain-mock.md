## 目标与边界

定义所有框架共同遵循的 IoT 业务契约与确定性 Mock 规则。每端独立维护领域类型、数据生成与接口代码，不依赖共享运行时包。只提供浏览器内的查询、命令和事件模拟；不实现真实 API、消息 Broker 或持久化服务。

## 实体与契约

Tenant、User、Role、Quota、EdgeNode、Product、ThingModel、DpRule、Device、TelemetryPoint、Alarm、RuleFlow、RuleExecution、Firmware、OtaTask。

每项契约必须定义字段类型、枚举、默认值、校验、权限、分页、排序、过滤、错误和实时事件。实体 ID 格式为 `{实体缩写}_{地区或日期}_{序号}`，时间以 ISO 8601 UTC 存储。

## 交互与规则

- 所有查询都接收显式 `seed`、租户上下文和时间范围。
- 同一 seed、查询参数和时区必须产生相同 DTO；页面不可直接调用 `Math.random()`。
- Mock API 可切换正常、慢速、局部失败、无权限和离线情景。
- 命令返回可追踪操作 ID；时序、告警、规则和 OTA 以事件流追加。

## 异常状态

无权限返回可解释的权限码；校验失败标记具体字段；离线、超时、冲突和部分失败均可被前端稳定显示。

## 验收条件

- Given 相同 seed 和 DashboardQuery，When 三端请求数据，Then 返回完全一致的业务值与排序。
- Given 请求无权限资源，When 查询，Then 返回统一错误语义且不泄露数据。
- Given 切换“局部失败”，When 查询列表，Then 页面仍展示成功分区并报告失败分区。

## 依赖与风险

领域模型决定后才能初始化三端业务应用。实体命名、数据保留和权限语义均必须由技术负责人审核。

## 2026-09-20 跨端契约增量

三端各自在 Node 环境导出相同固定场景的 Dashboard、地理、产品、设备、规则、固件、OTA 和租户查询结果，并通过隔离的内存 Storage 导出六个领域的状态操作、OTA 回滚与失败重试结果；外层诊断逐字段比较 102 个 DTO 与错误对象。各端仍独立维护业务实现与测试；具体覆盖和剩余矩阵见[契约测试计划](../../architecture/contracts/CONTRACT-TEST-PLAN.md)。本增量不构成 IOT-DOMAIN-001 完整验收。

## 2026-09-20 设备命令与事件历史契约增量

三端契约门禁现逐字段比对 **142** 个 DTO/错误结果，其中新增设备命令拒绝与离线历史、遥测消息去重与重载、故障告警确认及持久化状态。各场景由本端服务独立计算；完整事件和角色矩阵、REVIEW-003 与最终验收仍未完成。

## 2026-09-20 CI 跨端契约门禁增量

仓库诊断工作流新增独立跨端 DTO 比对作业：分别从三个应用自己的锁文件安装，再运行仓库外层比对命令；工具、文档、根入口及治理文件变更也触发诊断。当前本地门禁为 155 个结果，含需求范围变更、发布阻塞与材料补正结果；远端 CI 尚未执行，完整领域矩阵和最终验收仍待完成。
