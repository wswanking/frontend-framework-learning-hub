## 1. 产品概述

IoT Atlas 是一套仅在浏览器运行的物联网 SaaS 演示平台，也是 React、Vue、Angular 的工程化学习样本。三个框架将使用 TypeScript、相同的领域契约、固定 seed Mock 数据和验收用例，分别实现同一组 IoT 管理功能。

产品既要呈现真实的业务复杂度，也要保留完整的软件交付过程：需求、交互、方案、开发、测试、部署和验收均可追溯，AI 在每一阶段提升效率但不替代人工决策。

## 2. 目标、成功标准与边界

### 2.1 目标

1. 建立可持续的 AI 增强开发流程与留痕机制。
2. 用一个真实 IoT 业务场景串联前端基础、工程化与三大框架实践。
3. 提供可交互的全球 IoT 数据大盘与完整设备管理业务闭环。
4. 使三个框架的业务数据、权限和验收标准一致，便于横向学习。
5. 在无后端条件下完成本地开发、预览、测试、发布与验收演示。

### 2.2 成功标准

- 每个 `IOT-*` 需求能关联对应任务、Issue、审核、测试、发布和验收证据。
- 三端使用相同 seed 时，核心业务数据与查询结果一致。
- 用户能通过 Dashboard 理解设备、节点、地域、告警、消息量和 OTA 状态。
- 产品可以在桌面、平板和移动端查看关键数据，并支持明暗主题。
- AI 产生的变更均保留关联编号、验证结果和验收方式；本轮使用用户明确授权的自动化验收。

### 2.3 非目标

- 不连接真实设备、MQTT Broker、真实用户系统、对象存储或生产数据库。
- 不上传、存储或分发真实固件；文件与升级过程只在浏览器中模拟。
- 不承诺生产级监控、权限安全、计费、审计或海量实时数据能力。
- 不将三个框架的 UI 组件强行抽象为同一套实现。

## 3. 用户与权限

| 角色 | 核心目标 | 可执行操作 |
| --- | --- | --- |
| 平台管理员 | 观察全局运行状态和多租户配额 | 管理租户、全球节点、平台数据大盘 |
| 租户管理员 | 配置产品、设备、规则、固件和 OTA | 管理本租户业务资产与成员 |
| 运维工程师 | 处理设备和升级问题 | 查看诊断、告警、时序数据并操作 OTA |
| 数据观察员 | 读取运行数据 | 只读查看大盘、地图、设备与时序数据 |
| 产品/技术/发布负责人 | 查看交付证据 | 查看自动化验收、发布与回滚记录 |

前端演示通过 Mock 身份与路由权限体现差异；不实现真实登录服务。

## 4. 信息架构与关键交互

### 4.1 一级导航

```text
数据大盘
全球节点
产品中心（产品配置 / 物模型 / DP 点位规则）
设备中心（设备管理 / 详情 / 地理位置 / 时序数据）
规则引擎
固件与 OTA
租户管理
框架与组件实验室
交付看板（需求 / 任务 / Issue / 待审核）
```

### 4.2 关键用户流

1. 平台管理员进入数据大盘，按时间、租户和地域筛选，点击地图依次下钻到国家、节点与设备。
2. 租户管理员创建产品，维护物模型和 DP 转换规则，再创建或导入 Mock 设备。
3. 运维工程师进入设备详情，查看当前属性、历史时序、原始消息与告警，并发起远程控制或 OTA 演示。
4. 规则配置者以样例报文试运行规则流，查看每个节点的输入、输出和执行日志。
5. 发布负责人在正式发布前查看测试、Issue、审核和回滚材料，决定是否准入。

### 4.3 M1：持久导航与教学工程边界（2026-10-18）

关联 IOT-DASH-001、IOT-PLATFORM-003、IOT-DEVICE-001。用户授权按 M1→M4 分步实施；M1 首轮实施已完成；随后用户授权继续 M2，均可本地提交，不推送、创建 PR、合并或部署。

- 三端采用同一信息架构与交互契约，各自使用框架惯用路由、独立源码、依赖、Mock 和测试。
- AppShell、桌面侧栏和顶栏常驻；业务路由只更换内容，懒加载不卸载壳层。站内链接不整页刷新，跨框架入口可切换独立文档。
- 移动端导航默认收起，按钮展开；Escape 和成功导航后收起并返回菜单按钮焦点。菜单包含全部九个业务入口，活动项来自当前路由。
- 大盘→设备列表→详情→返回是首条验证链。设备详情以 `?device=` 表达，可直接访问、刷新、后退和前进；关闭返回列表，焦点回到仍存在的触发按钮。
- 未保存产品、规则、租户与设备草稿在路由离开时确认；取消保留草稿，确认放弃后继续。刷新/关闭使用浏览器原生离开提示。未知路由保留壳层并展示可恢复的不存在页面。
- 不无限缓存页面。页面草稿与订阅由页面拥有，离开后释放；URL 表达可恢复的详情位置，已保存 Mock 数据及既有主题偏好沿用各端本地存储。

M2 当前按设备模块补充规范落实列表与编辑返回链，M3 负责源码对应教学，M4 负责构建部署闭环。本轮自动检查不代替用户视觉批准或最终验收。

### 4.4 统一页面状态

每个业务页面必须设计并实现：加载、空数据、局部失败、无权限、正常数据、保存中、保存成功和保存失败状态。颜色不得作为告警或设备状态的唯一表达方式。

### IOT-DASH-001：IoT Dashboard 学习门户基线

**优先级：P0；状态：三端 Dashboard 增量实施中，待交互评审与最终验收；验收方式：用户交互评审与自动化证据审计。**

**目标**：根首页仅提供 React、Vue、Angular 三个应用入口；各应用内的大盘展示物联网平台全局运行态势，并使用项目交互图作为统一视觉和交互基线。

**功能要求**：

- 根首页不得承载业务大盘、业务导航、交付看板或框架对比内容，只展示三个可访问的应用入口。
- 三个应用保持相同的信息架构、导航名称、工作台层级、状态语义和关键操作路径，并分别采用各自主 UI 库实现。
- 展示接入设备、在线设备、消息量、活跃告警、OTA 成功率等关键指标及同比/环比变化。
- 展示六大洲设备分布、国家/节点设备和数据量排行，以及全球节点地图。
- 提供设备消息吞吐时序图、实时事件流和告警状态。
- 支持租户、时间范围、地域筛选；同一筛选条件应联动指标、地图、排行和图表。
- 支持亮色、暗色、跟随系统主题，用户选择持久化在本地。
- Dashboard 页面支持响应式布局和基础键盘可访问性。

**业务规则**：

- 地图下钻路径为洲 → 国家 → 节点 → 设备；没有子数据时显示空状态而非静默失败。
- 实时事件按发生时间倒序，最新事件在顶部；模拟事件频率和数据量必须由 Mock API 控制。
- 指标、排行和图表数据来自同一 `DashboardQuery`，不得分别在组件内随机生成。

**验收**：根首页只有三个应用入口；三端均能通过独立路由进入全部业务工作台，且在指定 seed 与筛选条件下指标、地图、排行、趋势图数据相互一致；移动端能读取指标、地图摘要和事件列表。

### IOT-DOMAIN-001：统一领域规范与各端固定 seed Mock 数据

**优先级：P0；状态：三端领域 Mock 增量实施中，待完整契约审核与最终验收；验收方式：契约测试与三端一致性测试。**

**目标**：定义三端一致的 IoT 业务事实、查询能力和可重复数据。

**范围**：

- 实体：Tenant、User、EdgeNode、Product、ThingModel、DpRule、Device、TelemetryPoint、Alarm、RuleFlow、Firmware、OtaTask。
- 查询：大盘、地域、设备、时序、告警、规则日志、固件、OTA、租户及配额。
- 命令：产品/物模型/DP 配置、规则试运行、设备控制模拟、固件登记、OTA 创建/暂停/重试/回滚。
- 异常：无权限、校验失败、冲突、离线、超时、部分失败和空结果。
- 实时事件：遥测、设备状态、告警、规则执行和 OTA 进度。

**业务规则**：

- 所有业务随机性来自显式 seed；同一 seed、查询和时区得到一致结果。
- 时间采用 ISO 8601 UTC 保存，界面按用户时区格式化。
- ID 格式为 `{实体缩写}_{地区或日期}_{序号}`。
- Mock API 必须支持分页、排序、筛选、搜索、延迟和可控失败。

**验收**：三个应用调用同一契约可得到相同 DTO 和错误语义；契约测试覆盖正常、空、失败和无权限场景。

### IOT-PLATFORM-003：三框架独立工程初始化

> 2026-09-16 用户调整架构要求：React、Vue、Angular 各自维护完整独立项目，所有应用代码与资源隔离，包括领域类型、业务规则、Mock、组件、样式、设计令牌、测试、依赖清单、锁文件与构建配置。三端共同遵循同一套功能、交互、字段和验收规范，不再通过共享运行时代码保持一致。统一构建仅在外层调用各项目构建命令并汇总产物。此要求优先于本文及历史文档中的共享包要求；当前已清理原实现，后续按完全隔离要求重新实现。

**优先级：P0；状态：三端独立工程已搭建，待完整业务与最终验收；验收方式：三端独立构建与门户可达性测试。**

**目标**：建立可独立构建、运行和测试的 React、Vue、Angular 应用，并在业务契约层保持一致。

**功能要求**：

- 分别建立 React、Vue、Angular 三个完整独立项目，各自维护目录和工程配置。
- 每个应用使用 TypeScript、独立路由、主题、状态管理、Mock 适配和测试入口。
- React 主 UI 库为 MUI，Vue 为 Element Plus，Angular 为 Angular Material；其他 Top 3 热门 UI 库仅用于实验室页面。
- 业务大盘默认使用 Apache ECharts；Chart.js 与 D3.js 作为同数据集对比实验。
- 三端各自维护领域类型、Mock、设计令牌及全部应用代码与资源，不跨应用导入，不依赖仓库公共运行时包。共同规范保留在文档中，各端自行实现和验证。

**验收**：三个应用可独立启动、构建和测试；同一契约测试和 seed 在三端通过；每端主 Dashboard 路由、主题和权限语义一致。

### IOT-QUALITY-001：独立诊断与验收环境

2026-09-16 用户授权先搭建诊断和验收环境。范围为三端独立工程工具链及最小诊断页面，不恢复旧业务代码。每端独立维护依赖、锁文件、静态检查、无浏览器组件测试、浏览器流程/无障碍检查与视觉回归配置。CI 分别安装、构建和验收，各端不得依赖父目录或兄弟项目。

当前实施范围和验证证据见[诊断与验收环境](../architecture/QUALITY.md)；此段记录 2026-09-16 的诊断基座阶段。
